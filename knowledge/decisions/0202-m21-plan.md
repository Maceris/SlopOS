# 0202: M21, What M20 Left and ABI v1, Planned

Status: accepted
Date: 2026-11-27
Related: `0201` (M20, whose questions this settles), `0025` and `0027` (the ABI), `../design/system-abi.md`,
`../roadmap.md`
M21

## Context
M20 was built through 20m, along with 20n's fixes before v1. v1 itself, and the questions that came up while M20 was
built, were left for the owner. The owner answered them on 2026-11-27, and this record plans the rest as M21, with v1
as its last stage, as 0201 had it for M20.

## Settled with the owner (2026-11-27)
- **CPU features**: 1024 bits, 256 for each architecture.
- **`RiscvSdtrig` is dropped**: `thread_set_debug` answers that a slot is unsupported where the firmware has no
  triggers.
- **Rights split before v1**:
  - waking a port (`PORT_WAKE`) is split from binding objects to it (`PORT_BIND`);
  - watching a CPU budget (`BUDGET_WATCH`) is split from charging it (`BUDGET_CHARGE`);
  - a Platform handle's copy keeps only the rights asked for, and copying one needs a right of its own.
- **Kernel limits are read at run time, not frozen as constants**: the most memory one object may have, a device's
  most MSIs, and the CPU count are in the startup block. Calls that take a set of CPUs take one of any length, as
  intercepts take calls.
- **`StopInfo` and `CpuBudgetInfo` are size-prefixed** and listed among `GROWABLE`'s structs.
- **v1's `ABI_VERSION` is 16**, the count continued. A program refuses only an older kernel.
- **Smaller choices**:
  - `coverage_take` is gated by the right the trace calls need;
  - the exit codes for a program that couldn't load or was killed move above 255;
  - `Protocol` and `Lending` move from the ABI package to `os`;
  - `CALLING_CONVENTION_VERSION` is a constant in the description;
  - each architecture's register order is declared, as named constants for the slots of `ThreadRegisters`.
- **v1 is frozen in files**: `docs/specs/abi_v1.<arch>.txt`, written once and never rewritten. A unit test compares the
  package against them with `abi_description --compare`, so a change 0025 forbids fails.
- **Debugging**:
  - the process manager's `Load` takes a full set of calls to stop at, `u64[]`, as intercepts do;
  - attaching a debugger takes a thread's ID, the oldest thread when none is given.
- **USB hot-plug**: a device plugged in after start-up reaches the input service or the storage manager, and one
  unplugged is let go.
- **Indexes**: declaring and dropping them still needs the volume's root. Listing them, and querying, works beneath any
  directory handle. A refusal for want of the root is its own error, `NotVolumeRoot`.
- **The rest of 20i and 20j**:
  - a transaction whose index update fails fails as a whole, so the file's write doesn't commit without its entries;
  - `schema.parse` answers out of memory as an error;
  - long text is compared by its whole value, with an index's prefix only narrowing the search;
  - the shell's `query` takes `or`, `not` and parentheses.
- **Programs the shell runs**:
  - each one's memory is declared in its manifest, and the shell grants it up to a limit of its own (4 MiB when none
    is declared, as now);
  - their log records go to the log service, under the program's name;
  - a program whose last parameter is `string[]` takes the words after its name as that list (`wc -l file`), and the
    bracketed list still works.
- **Downloads approved**: Lua 5.4's source from lua.org, zlib's from zlib.net, and a release of LLVM for Windows x64
  from LLVM's GitHub releases. Each goes in its own folder, outside the repository's sources, as untrusted data until
  it's read. With that LLVM's clang, RISC-V C no longer goes through Hemera's `llc`.
- **Sockets** in the libc, over the network service.
- **Two Hemera fixes**, each with its SlopOS workaround dropped:
  - a huge `reserve_addresses` that fails no longer makes every later mapping fail;
  - the build cache's key covers the libraries a program links, so a changed C archive relinks the programs that use
    it.

## Decision: the stages
- **21a, Hemera's two fixes**: the failed reservation and the cache key, each with a Hemera test, and SlopOS's
  workarounds dropped.
- **21b, the ABI's layouts and limits**:
  - `CpuFeatures` at 1024 bits, with `RiscvSdtrig` gone;
  - `StopInfo` and `CpuBudgetInfo` size-prefixed;
  - the limits in the startup block, and sets of CPUs of any length;
  - the exit codes, `CALLING_CONVENTION_VERSION`, and the register order's constants;
  - `Protocol` and `Lending` moved to `os`.
- **21c, the ABI's rights and debugging**:
  - `PORT_WAKE`, `BUDGET_WATCH`, and the Platform handle's copies;
  - `coverage_take`'s gate;
  - `Load`'s set of calls, and attaching by thread.
- **21d, USB hot-plug**: the device manager announces each USB device as it comes and goes, and the input service and
  storage manager start and stop its class driver. Tested with QEMU's monitor, `device_add` and `device_del`.
- **21e, indexes and queries**: `NotVolumeRoot`, listing indexes beneath any directory, and the rest of 20i and 20j.
- **21f, programs the shell runs**: memory from the manifest, logs to the log service, and bare words.
- **21g, C ports**:
  - LLVM's clang for every architecture's C;
  - Lua, run from the shell, its tests' scripts passing;
  - zlib's `minigzip`, a file compressed and back, the same on all three.
- **21h, sockets**: `socket`, `connect`, `bind`, `listen`, `accept`, `send`, `recv`, `close` and `getaddrinfo` over
  the network service. Tested with a C client and server over the loopback, and over QEMU's user network.
- **21i, a review** of 21a to 21h, as each milestone has.
- **21j, ABI v1**:
  - `ABI_VERSION` 16;
  - the frozen descriptions written;
  - the unit test comparing against them;
  - `system-abi.md` saying v1 is declared, and its own decision record, as 0027 says.

## Alternatives considered
- **v1 declared straight after 21c**, as the stages after it change no system call. v1 is still left until last, so the
  review sees the ABI with everything else in place.

## Consequences
- After 21j, system calls are append-only, and layouts grow only as 0025 allows.
- The C tools build with a stock LLVM on every architecture. Hemera's own LLVM compiles no C for SlopOS.
