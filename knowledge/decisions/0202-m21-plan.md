# 0202: M21, What M20 Left and ABI v1, Planned

Status: accepted
Date: 2026-11-27
Related: `0201` (M20, whose questions this settles), `0025` and `0027` (the ABI), `../design/system-abi.md`,
`../roadmap.md`
M21

## Context
M20 was built through 20m, along with 20n's fixes before v1. v1 itself, and the questions that came up while M20 was
built, were left for the owner. The owner answered them on 2026-11-27, and this record plans the rest as M21, with v1
as its last stage, as 0201 had it for M20.

## Settled with the owner (2026-11-27)
- **CPU features**: 1024 bits, 256 for each architecture.
- **`RiscvSdtrig` is dropped**: `thread_set_debug` answers that a slot is unsupported where the firmware has no
  triggers.
- **Rights split before v1**:
  - waking a port (`PORT_WAKE`) is split from binding objects to it (`PORT_BIND`);
  - watching a CPU budget (`BUDGET_WATCH`) is split from charging it (`BUDGET_CHARGE`);
  - a Platform handle's copy keeps only the rights asked for, and copying one needs a right of its own.
- **Kernel limits are read at run time, not frozen as constants**: the most memory one object may have, a device's
  most MSIs, and the CPU count are in the startup block. Calls that take a set of CPUs take one of any length, as
  intercepts take calls.
- **`StopInfo` and `CpuBudgetInfo` are size-prefixed** and listed among `GROWABLE`'s structs.
- **v1's `ABI_VERSION` is 16**, the count continued. A program refuses only an older kernel.
- **Smaller choices**:
  - `coverage_take` is gated by the right the trace calls need;
  - the exit codes for a program that couldn't load or was killed move above 255;
  - `Protocol` and `Lending` move from the ABI package to `os`;
  - `CALLING_CONVENTION_VERSION` is a constant in the description;
  - each architecture's register order is declared, as named constants for the slots of `ThreadRegisters`.
- **v1 is frozen in files**: `docs/specs/abi_v1.<arch>.txt`, written once and never rewritten. A unit test compares the
  package against them with `abi_description --compare`, so a change 0025 forbids fails.
- **Debugging**:
  - the process manager's `Load` takes a full set of calls to stop at, `u64[]`, as intercepts do;
  - attaching a debugger takes a thread's ID, the oldest thread when none is given.
- **USB hot-plug**: a device plugged in after start-up reaches the input service or the storage manager, and one
  unplugged is let go.
- **Indexes**: declaring and dropping them still needs the volume's root. Listing them, and querying, works beneath any
  directory handle. A refusal for want of the root is its own error, `NotVolumeRoot`.
- **The rest of 20i and 20j**:
  - a transaction whose index update fails fails as a whole, so the file's write doesn't commit without its entries;
  - `schema.parse` answers out of memory as an error;
  - long text is compared by its whole value, with an index's prefix only narrowing the search;
  - the shell's `query` takes `or`, `not` and parentheses.
- **Programs the shell runs**:
  - each one's memory is declared in its manifest, and the shell grants it up to a limit of its own (4 MiB when none
    is declared, as now);
  - their log records go to the log service, under the program's name;
  - a program whose last parameter is `string[]` takes the words after its name as that list (`wc -l file`), and the
    bracketed list still works.
- **Downloads approved**: Lua 5.4's source from lua.org, zlib's from zlib.net, and a release of LLVM for Windows x64
  from LLVM's GitHub releases. Each goes in its own folder, outside the repository's sources, as untrusted data until
  it's read. With that LLVM's clang, RISC-V C no longer goes through Hemera's `llc`.
- **Sockets** in the libc, over the network service.
- **Two Hemera fixes**, each with its SlopOS workaround dropped:
  - a huge `reserve_addresses` that fails no longer makes every later mapping fail;
  - the build cache's key covers the libraries a program links, so a changed C archive relinks the programs that use
    it.

## Decision: the stages
- **21a, Hemera's two fixes**: the failed reservation and the cache key, each with a Hemera test, and SlopOS's
  workarounds dropped.
- **21b, the ABI's layouts and limits**:
  - `CpuFeatures` at 1024 bits, with `RiscvSdtrig` gone;
  - `StopInfo` and `CpuBudgetInfo` size-prefixed;
  - the limits in the startup block, and sets of CPUs of any length;
  - the exit codes, `CALLING_CONVENTION_VERSION`, and the register order's constants;
  - `Protocol` and `Lending` moved to `os`.
- **21c, the ABI's rights and debugging**:
  - `PORT_WAKE`, `BUDGET_WATCH`, and the Platform handle's copies;
  - `coverage_take`'s gate;
  - `Load`'s set of calls, and attaching by thread.
- **21d, USB hot-plug**: the device manager announces each USB device as it comes and goes, and the input service and
  storage manager start and stop its class driver. Tested with QEMU's monitor, `device_add` and `device_del`.
- **21e, indexes and queries**: `NotVolumeRoot`, listing indexes beneath any directory, and the rest of 20i and 20j.
- **21f, programs the shell runs**: memory from the manifest, logs to the log service, and bare words.
- **21g, C ports**:
  - LLVM's clang for every architecture's C;
  - Lua, run from the shell, its tests' scripts passing;
  - zlib's `minigzip`, a file compressed and back, the same on all three.
- **21h, sockets**: `socket`, `connect`, `bind`, `listen`, `accept`, `send`, `recv`, `close` and `getaddrinfo` over
  the network service. Tested with a C client and server over the loopback, and over QEMU's user network.
- **21i, a review** of 21a to 21h, as each milestone has.
- **21j, ABI v1**:
  - `ABI_VERSION` 16;
  - the frozen descriptions written;
  - the unit test comparing against them;
  - `system-abi.md` saying v1 is declared, and its own decision record, as 0027 says.

## Alternatives considered
- **v1 declared straight after 21c**, as the stages after it change no system call. v1 is still left until last, so the
  review sees the ABI with everything else in place.

## Consequences
- After 21j, system calls are append-only, and layouts grow only as 0025 allows.
- The C tools build with a stock LLVM on every architecture. Hemera's own LLVM compiles no C for SlopOS.

## As Built: 21a, Hemera's two fixes (2026-11-27)
- **Reservations**: base's `map_pages` makes its memory object before it takes the free range's addresses, so a size
  the budget can't give takes none; `reserve_addresses` checks the size before rounding it and moves its offset by a
  compare-and-swap only past what fits; `release_addresses` gives back the last reservation when its mapping fails.
  The libc's check against the budget before asking the heap is gone; test_libc asks for `SIZE_MAX / 2` and twice for
  512 GiB, each NULL, then maps a block of its own.
- **The build cache**: a program's key has the bytes of each file in its library folders the linker could take for a
  library it names (`lib<name>.a` or `.so`, `<name>.lib`), and a target's record each library folder's files by name,
  size and modification time, so a changed library builds the target and relinks its program (Hemera's
  `Build.LinksAgainWhenALinkedLibraryChanges`). `tools/c_libraries.py` writes the libraries into `c/` alone, removing
  the keyed folders and `key.txt` an earlier build left, and the build package gives `c/` as the library folder.

## As Built: 21b, the ABI's layouts and limits (2026-11-27)
- **CPU features**: `CpuFeatures` is 1024 bits (`u64[16]`, 128 bytes): x86-64's from 0, AArch64's renumbered from 256,
  RISC-V's from 512, 768 to 1023 kept for another architecture. `RiscvSdtrig` is gone: the SBI's triggers are found by
  `thread_set_debug`, which refuses a slot with `BadRegisters` where there are none, and test_control's debugger test
  skips on RISC-V when its first breakpoint is refused that way, telling its copy to end first.
- **Size-prefixed results**: `StopInfo` (`size`, `point`, `thread`, `number`, `reserved`, `address`; 32 bytes,
  `STOP_INFO_SIZE`) and `CpuBudgetInfo` (`size`, `reserved`, then its seven words; 64 bytes, `CPU_BUDGET_INFO_SIZE`),
  each `size` defaulting to its own. The kernel reads the caller's size, refuses one under 8 (`BadBuffer`), writes as
  many bytes of its own as fit and sets `size` to how many. `cpu_budget_info` takes a `ptr[mut CpuBudgetInfo]`;
  `CPU_BUDGET_INFO_WORDS` is gone. Both are among the comparison's `GROWABLE` structs.
- **Sets of CPUs**: `CpuBudgetInfo` lost its `cpus`. `cpu_budget_set_cpus` takes a `u64[]` of any length, CPU n bit
  n % 64 of word n / 64; the kernel, at most 64 CPUs (`boot_protocol.MAX_CPUS`), reads the first word and ignores the
  rest, and an empty set is refused as one with none online. `cpu_budget_cpus` (call 100) writes the budget's set,
  masked to the CPUs there are, as many words as fit with zeros past them, and gives how many words the kernel's set
  has, 1. `add_cpu` and `has_cpu` in the package. test_affinity checks an empty set, a set longer than the kernel's,
  and the words `cpu_budget_cpus` writes.
- **Limits in the startup block**: `max_memory_size`, `max_device_msis` and `cpu_count` after `cpu_features`, mirrored
  in base's `SlopOsStartup` and asserted; the root task writes them from the kernel's own constants, now
  `arch_interface.MAX_MEMORY_SIZE` (1 GiB) and `MAX_DEVICE_MSIS` (32), and `kernel.cpus.count`, and the process
  builder copies them from its own block. The package's `MAX_MEMORY_SIZE` and `MAX_DEVICE_MSIS` are gone.
- **Exit codes**: `EXIT_WRONG_ABI` 256, `EXIT_MISSING_GRANT` 257 (base's `SLOP_OS_EXIT_` too), above any C program's own
  status; test_exits' tests are named for them.
- **The register order declared**: each architecture's `REGISTER_` constants (x86-64's every register; AArch64's
  `REGISTER_X0`, `FP`, `LR`, `SP`, `PC`, `PSTATE`; RISC-V's `X0`, `RA`, `SP`, `GP`, `TP`, `FP`, `A0`, `PC`), and
  `REGISTER_PC`, `REGISTER_SP` and `REGISTER_FP` on all three, so each description covers its order. crash_reports'
  `PC_REGISTER`, `FRAME_REGISTER` and `STACK_REGISTER` stay literals, asserted against them, as a cast constant doesn't
  prove an index in bounds (hemera-feedback.md).
- **`CALLING_CONVENTION_VERSION`**, 1: the system calls' register convention, in the description.
- **`Protocol` and `Lending`** moved to std's `os` (`slop_os_protocols.hsc`), as `os.Protocol`; every protocol package
  imports `os` already (dir and os import each other, which Hemera takes), so no package of their own was needed.
- **`ABI_VERSION` stays 15**: v1 is 16, the owner's, and 21j's; nothing older than these changes runs against them, as
  every program is built with the kernel.
- **Docs**: `system-abi.md`'s table and §6, `system_calls.md`'s calls 26, 42, 53, 61 and 71, the `StopInfo` table and
  the errors; `programs.md`'s exit codes; the three descriptions regenerated.

## As Built: 21c, the ABI's rights and debugging (2026-11-27)
- **Ports**: `RIGHT_PORT_WAKE` (bit 10) is what `port_wake` needs; `RIGHT_PORT_BIND` binds, sets timers and unbinds.
  test_ports checks a copy that may only bind can't wake, and one that may only wake can't bind but wakes.
- **Memory budgets**: `RIGHT_BUDGET_WATCH` (bit 9) is what `memory_budget_set_threshold` and a port binding to a
  budget need, in place of `RIGHT_BUDGET_CHARGE`; describing one still needs no right. A launched program's own budget
  has it (base's launcher and the process builder), as the bundle store and the session manager watch theirs.
  test_memory checks a watcher can set a threshold and bind but not pay, and a charger can do neither.
- **The Platform**: `RIGHT_PLATFORM_DEVICES` (bit 8) for every hardware call (controllers, IRQs, physical memory,
  devices, DMA domains, IOMMUs, I/O ports, a controller's source), `RIGHT_PLATFORM_POWER` (bit 9) for `power_set_off`,
  `power_set_reset` and `power_end_with`, and `RIGHT_PLATFORM_DUPLICATE` (bit 10), which `handle_duplicate` needs of a
  Platform handle besides `RIGHT_DUPLICATE`; a copy keeps only the rights asked for, as any does. The root task gives
  the devices tests `DEVICES` and the platform service `DEVICES` and `POWER`, neither `DUPLICATE`; its own handle has
  every right. test_devices checks its copy can't be copied and can't set the reset.
- **`coverage_take(log, counters)`**: the kernel's debug log with `RIGHT_DEBUG_LOG_TRACE`, as `trace_set` and
  `trace_read` need; `CoverageError` gains `InvalidHandle`, `ObjectGone`, `MissingRight` and `WrongKind`, the tags
  every enum shares. The root task gives the system call fuzzer, alone of the tests, a log that may trace.
- **`Load`'s calls**: `intercept_calls` is a `Relative[u64]`, a set of any length as `intercept_attach` takes; the
  launcher sends four words of every call for a debugger or given points (calls the kernel hasn't are ignored), none
  otherwise; the manager passes the set as it came.
- **Attaching by thread**: `debug attach name [thread]` looks at the thread of that ID, as `threads` lists them, or
  without one the oldest; an ID the program hasn't lets it go at once with an error. The boot test attaches without
  one, so the ID's path is checked only by its build.
- **The RISC-V latency test** failed twice under load during 21b's focused runs (99.9th percentile 8.3 ms against
  5 ms) and passed on HEAD and on 21b afterwards: it's near its bound under TCG, not broken by these stages.


## As Built: 21d, USB hot-plug (2026-11-27)
- **The supervisor watches each host controller's driver** once start-up's devices are all there (`start_usb`, then
  `serve_usb`): its usb_bus connection bound to the port under `USB_KEY` (10000) plus its entry, a Next held on it
  whenever none is. An Attached is kept and its class driver started as at start (`keep_usb`), in a gone interface's
  place in `usb` and a gone class driver's ended entry in `started`, so plugging in again and again fills neither; a
  Detached (`detach_usb`) closes the supervisor's end of every connector to its class driver, then kills the driver,
  marked `usb_gone` so it isn't started again. A host controller's driver started again has a new connection, watched
  in place of the last, and what it had found is let go of, as it finds it all again.
- **A new protocol, hotplug** (`src/protocols/hotplug`): the input service's and storage manager's `devices` grant, a
  channel the supervisor makes at each one's start and sends `Added(connector)` on, unanswered, for each class driver
  started after start-up (`announce_usb`). A disk plugged in with no storage manager running, as with no disk at boot,
  starts the storage manager, given it as a disk at start is. Unplugging isn't told: the service sees its connector's
  other end closed. Only the supervisor holds the sending end, so nothing else gives a service a device.
- **The input service** takes a keyboard plugged in into the first free place, new, so its code has to be typed on it
  (the trusted path, as for any keyboard found after start); one whose driver can't be dialed again once its channel
  fails is gone, its place free. Its dial closes the port it makes for the connector (it was left open each time).
- **The storage manager** holds a disk plugged in as one given at start (`add_disk`), in a gone disk's place, its
  partitions in gone partitions' places; each disk's connector is watched for its other end closing (`DISK_GONE_KEY`),
  which kills its partition server and everything served from its partitions, and leaves its partitions listed with a
  type of all zeros, so the others' indexes, which clients hold, stay.
- **System records**: `MAX_SERVED` 8 to 16 (the supervisor serves hotplug too), so the magic is `SLOPSYS4`.
- **Tests**, on all three: a keyboard plugged in after start, typed on once its code is, unplugged (its driver let go,
  its place freed) and plugged in again, new again in the same place; and a stick plugged in with no disk at boot, the
  storage manager started for it and `test_hotplug`'s disk check passing on its FAT volume (writing block 2049),
  unplugged (partition and FAT servers let go) and plugged in again, through the devices channel. boot.py's
  `--hotplug` steps (`add:keyboard`, `add:stick`, `del:ID`, `wait:TEXT`) drive QEMU's `device_add` and `device_del`;
  `--input-bus=usb-later` and `--disk-bus=usb-later` give an xHCI controller with nothing on it, the stick's drive a
  `-blockdev` node, since a `-drive` is deleted with its device and couldn't be plugged in again; a keyboard line
  `\l{text}` waits for a serial line, and `\code` looks past the last code it typed.
- **Left**: connectors aren't reused (`MAX_CONNECTORS`, 32 over the supervisor's life), and each device plugged in
  takes one; a mouse or tablet plugged in takes a keyboard's place in the seat, as at start.

## As Built: 21g, C ports (2026-11-27)
- **One clang for every architecture**: `tools/c_libraries.py` takes CLANG if set; else the first clang with the
  architecture's backend of an LLVM release's (`LLVM`, then `LLVM_RELEASES`: `C:/Program Files/LLVM/bin`, and releases
  unpacked as `D:/Programs/System Tools/llvm-*-download/clang+llvm-*/bin`, the newest first), the PATH's and Visual
  Studio's. LLVM 23.1.5's clang (its Windows x64 release, downloaded with the owner's approval, its SHA-256 the one
  GitHub publishes) compiles all three, so RISC-V's C no longer goes through Hemera's `llc`. The bitcode and `llc` path
  stays only as the fallback where no clang found has the backend. LLVM 23's assembler holds Zicfiss experimental, so
  the libc's RISC-V setjmp writes `ssrdp t0` as its encoding (`.4byte 0xcdc042f3`, llvm-mc's).
- **Lua 5.4.9** (lua.org's, SHA-256 as published): `src/apps/lua`, its sources unchanged in `c/` but for `luac.c`,
  its copyright and MIT license in `LICENSE.txt`, and a Hemera entry, as wc's, running lua.c's `main` with the shell's
  directory and terminal. Lua's default configuration (ANSI C: no `dlopen`, `popen` or `mkstemp`) needs nothing the
  libc hasn't. The shell's 4 MiB budget is enough for its checks; a bigger script needs 21f's manifest budgets.
- **zlib 1.4's minigzip** (zlib.net's, SHA-256 as published): `src/apps/minigzip`, zlib's sources and
  `test/minigzip.c` in `c/`, its license in `LICENSE.txt`. One change, marked where it's made, as zlib's license asks:
  `zconf.h` has `unistd.h` on SlopOS, as `./configure` would find. The libc gains `fcntl` (`F_GETFD`, `F_SETFD`,
  `F_GETFL`, `F_SETFL`, `FD_CLOEXEC`; `F_DUPFD` and others EINVAL), which gzlib calls; test_libc checks it.
- **Tests**: `test_c_ports` writes Lua's scripts and minigzip's input beneath the shell's directory (its folder's
  `.gitattributes` keeps them LF, so their bytes are the same on every checkout). The boot test, on all three, runs 39
  checks in Lua (strings and patterns, utf8, tables and metatables, closures, coroutines, errors and tracebacks,
  `string.format`, integer and float math, io beneath the directory, `arg`), an error nothing catches (its message,
  and `lua ended with 1`), and `-e`; then minigzip compresses checks.lua's 4373 bytes to the same 1865 bytes on every
  architecture (the line a native build of the same zlib gives, but for the header's OS byte, 3), and gives them back.

## As Built: 21e, indexes and queries (2026-11-27)
- **Authority**: declaring and dropping an index need a dir connection to the volume's root; one beneath it is
  refused with files' new `NotVolumeRoot` (18), one read only or reached through a stored link with `ReadOnly` as
  before (`root_refusal`). Listing them (`Indexes`) works on any dir connection, so std's `index_of`, `where_number`
  and `where_text` take any directory of the volume, and the shell's `query` lists them beneath its own directory,
  opening the home's root only for `--index`. std maps `NotVolumeRoot` to `AccessDenied`.
- **A commit is all or none**: the volume server indexes what changed before it writes the tree (`commit` calls
  `slopfs.index_changes` itself); when that fails for want of memory, of space for a node, or because a changed file
  can't be read, it goes back to the last commit (`last_committed`, kept as each commits, through the transactions'
  `undo`: the container's Abandon, then `slopfs.forget`), every change since then forgotten as a crash would, logs
  it, begins its live queries again (`restart_lives`), and serves on; a transaction's commit answers why
  (`commit_failure`: NoMemory, NoSpace, DeviceError) rather than DeviceError, nothing of it kept. An index's record
  that doesn't check out (`Corrupt`) still fails the volume. Writes acknowledged since the last commit, a second at
  most, are lost with it, as a crash loses them: they were never durable.
- **schema.try_parse** (Hemera's std): `parse` as before, but OutOfMemory given back, nothing kept (each list's add
  through `add_read`, `Schema.short_of_memory`); `parse` calls it and keeps calling the assertion handler. slopfs's
  `field_of` takes it, so `declare_index` answers NoMemory, the last place the volume server didn't.
- **Long text compared whole**: a plan keeps a text constant longer than an index's records do (255 bytes) whole, in
  `Plan.texts` (`PLAN_TEXT_BYTES`, 4096 together, past which a query is `WrongType`), each term's `whole_offset` and
  `whole_bytes`; where a file's kept text and the constant are both 255 bytes and alike, `holds` compares the file's
  whole field, read from its value (`whole_text_order`), with the whole constant. `=` and `≠` of a longer constant
  are no longer refused; the key's 8 bytes still bound the walk.
- **The shell's query** reads `and`, `or`, `not` and parentheses, not tightest and or loosest, into postfix terms (at
  most query's MAX_TERMS, 32): bare words for and and not, and a text argument, which query splits itself (spaces,
  parentheses, '-quoted values), for or and parentheses, as those are the shell's own syntax between commands.
- **Tests**: slopfs's `a_long_text_is_compared_by_its_whole_value_past_what_an_index_keeps` (texts alike in their
  first 600 bytes, by =, ≠, <, >, >=, and a short one) and
  `an_index_that_cant_be_made_at_commit_leaves_the_changes_to_be_forgotten_whole` (each allocation of indexing failed
  in turn, then forgotten to the last commit: the write and a new file gone, the volume not failed, the next commit
  indexed); Hemera's schemas scenario `try_parse_gives_back_running_out_of_memory`; disk_check's query check refused
  beneath the root with `NotVolumeRoot`, an index found and a query of an or of a not asked beneath it, and two titles
  alike in their first 300 bytes told apart; the shell's reading test declares two indexes of `Made`, asks with and
  and not as words, with or and parentheses in a text, one matching nothing, and one whose ( has no ).
- **Not tested at boot**: the server's going back from a commit whose indexes fail, which a booted system can't be made
  to do on purpose; its slopfs side is the hosted test above.

## As Built: 21h, sockets (2026-11-27)
- **Over std's net**: `src/libc/sockets.hsc`. TCP goes through `net.open`, `listen`, `ask_accept` and `take_accepted`,
  `poll`, `read_now` and `write_now`; UDP through the datagrams protocol, a Receive kept asked, the datagram it brings
  stashed. The connection to the network service is `Start.network`, which a C program asks for with an entry
  parameter `os.Channel[network.Network]`; the shell grants it as a native program's. A socket is a descriptor in the
  libc's table, so `read`, `write`, `close`, `fcntl`'s `O_NONBLOCK` and `fstat` (`S_IFSOCK`) take it.
- **One port for every socket**: each socket's channel is bound to the libc's own port, under its descriptor's number
  (`net.serve_on`, `net.listener_on`, a port_bind for UDP). Whatever waits, a blocking call or `poll`, waits on that
  port, then looks again at what it waits for, so `poll` and `select` (C, over `poll`) wait on many sockets at once.
  A file, stdin, stdout and stderr are always ready.
- **What's there**: `socket` (AF_INET, AF_INET6; SOCK_STREAM, SOCK_DGRAM, with SOCK_NONBLOCK and SOCK_CLOEXEC),
  `bind`, `listen`, `accept`, `connect`, `send`, `sendto`, `recv`, `recvfrom` (MSG_PEEK, MSG_WAITALL, MSG_DONTWAIT),
  `shutdown`, `setsockopt` and `getsockopt`, `getsockname`, `getpeername`, `poll`, `select`, `getaddrinfo`,
  `freeaddrinfo`, `gai_strerror`, `getnameinfo` (numeric only), `inet_pton`, `inet_ntop`, `inet_addr`, `inet_aton`,
  `inet_ntoa`, `htons` and the rest. The options:
  - SO_RCVTIMEO and SO_SNDTIMEO bound a receive's and a send's waits.
  - SO_ERROR gives the last connect's failure.
  - SO_TYPE gives the socket's type; SO_SNDBUF and SO_RCVBUF give a ring's bytes.
  - SO_REUSEADDR, SO_KEEPALIVE, SO_BROADCAST and TCP_NODELAY are kept, changing nothing.
  - Others are ENOPROTOOPT.

  The headers are `sys/socket.h`, `netinet/in.h`, `netinet/tcp.h`, `arpa/inet.h`, `netdb.h`, `poll.h` and
  `sys/select.h`, plus errno.h's network errors, Linux's numbers, with strerror's words.
- **Choices**:
  - `connect` always waits for the handshake, O_NONBLOCK or not; there's no EINPROGRESS.
  - `close` finishes a connection and waits up to 5 s for what was written to be acknowledged before it closes the
    channel, which would otherwise reset it and lose those bytes.
  - `bind`'s address is taken but not kept, as the service listens on its interfaces' addresses.
  - A TCP socket can't listen on port 0.
  - A UDP socket's made with the service on its first `bind`, `connect` or `sendto`.
  - A connected UDP socket drops datagrams from any other peer.
  - getaddrinfo reads numeric hosts itself and asks the service for names; a service is a port's number or one of a
    few names (echo, ssh, domain, http, ntp, https).
- **No loopback**: SlopOS's network stack has no loopback interface, and it drops what comes from its own address, so
  a client and a server in SlopOS can't reach each other. The test's server is reached from the development machine
  instead, through QEMU's forward, as test_network's is.
- **Tests**: test_network with `c_sockets` runs `c/sockets.c`, test_network_c's library, through `libc.run`, its lines
  the program's; the boot test (on all three) ends once they're all there, its test_settle only a bound. It has:
  - addresses' text both ways, and byte order;
  - a TCP echo of 64 KiB through poll, O_NONBLOCK writes and receives, `shutdown`, the end read as 0, and EPIPE;
  - a UDP echo by `sendto` and through a connected socket, with a receive timing out;
  - peer.slopos.test resolved to fec0::2 and 10.0.2.2 and reached by name, and missing.slopos.test as EAI_NONAME;

## As Built: 21f, programs the shell runs (2026-11-27)
- **Memory from the program**: a program's root package declares `PROGRAM_MEMORY : u64`, the bytes it asks to run on;
  the build package's manifest check writes it beside the manifest as `<name>.memory`, in decimal (0 for none), the
  store builder puts it in the program's bundle (`Bundle.memory`, `bundle.bundle_memory`), the session manager reads
  it with the bundle's references (its known-refers cache) and gives it with Find (`programs.Program.memory`). The shell
  gives that, or `PROGRAM_BUDGET`'s 4 MiB for 0, and refuses a program that asks for more than `MAX_PROGRAM_BUDGET`,
  24 MiB, before it starts. SlopOS-only: no Hemera change, as `compiler.find_constant` reads the constant.
  `SHELL_BUDGET` is 40 MiB (was 16), room for its own and one such program, and the session manager's budget 128 MiB
  (was 96), to keep the room it had. Lua asks for 16 MiB; a script holding about 6 MiB, which 4 MiB can't, runs.
  A script's shell, on `SCRIPT_BUDGET`'s 10 MiB, can't run a program asking for more than fits in it, which fails to
  start for want of budget.
- **The heap's big blocks**: base's page heap gives a block over 2 KiB pages of its own, a memory object with a page in
  front for its handle, so a 4000-byte string took 12 KiB and Lua's first big script ran out of 16 MiB; the script's
  pieces are 1900 bytes, in the 2 KiB class (hemera-feedback.md).
- **Logs**: the programs protocol has `Events(name)`, answered `EventsOpened(events.Source)`, and `RetireEvents(ring)`,
  answered `Done`, on a session's own connection and a finder's (a script's shell's); the session manager opens a
  source of the program's name, its budget the session's for its programs' records, as it does for its own programs.
  The shell asks for one as it launches a program, gives it a duplicate that can be read, written and moved, keeps the
  owning handle, and gives it back once the call ends (`end_call`). A program without one, as when the events service
  refuses its name, runs as before. Records come out as any program's, `[user] test_libc_files: ...`; test_libc_files
  logs how its C ended (but for C's exit, which ends it there), which the boot test expects. Like the session
  manager's own, a source's name is the program's, not tied to the session.
- **Bare words for a list of text**: when the arguments reach a program's last positional parameter (a value's,
  directory's or file's) and it's `string[]` or `string[]?` (`is_text_list`: a view or dynamic array of strings), that
  argument and every one after it are the list's items, a bare word as written and anything else as it evaluates. A
  `--name` the program has still names its parameter; one it hasn't is an item, the list's first if it's where the list
  begins, joined with what follows its name with no space between (`--exit=-1`, which the parser splits). One argument
  alone that isn't a bare word (`[list]`, `$name`) is the list itself, so `wc ["-l", "file"]` still works. The call
  still ends at the shell's own `| ; ) } ? &` and `or`. `design/shell.md` §3 says so.
- **Tests**: "runs C from the shell on the libc" runs `wc libc_words.txt`, `wc -l libc_words.txt nothing.txt`,
  `wc ["-l", "libc_words.txt"]` and `test_libc_files --exit=-1`, and expects test_libc_files' record on the serial
  log; "runs Lua and minigzip" runs `lua big.lua`. With them on main, the libc's C tests, the sockets test (21h), the
  manifest calls, pipelines and the shell language tests, on all three.

## As Built: 21i, the review, part A (2026-11-27)
A review of 21a to 21h, read only, its findings checked against the code; part A fixed those in the volume server,
slopfs, the shell and the session manager, and the owner's decision on programs' memory.
- **Going back ends what it forgot**: after a failed index update goes back to the last commit, `undo` ends
  (`end_forgotten`) every live volume connection to an object numbered at or past the commit's `next_object`, which
  the volume gives out again, so a client's writes through one can't reach the next object of that number; a
  snapshot's are left. Its release on dropping finds nothing to give back. No boot test can make indexing fail on a
  running system, as 21e found; covered by reading, and the hosted test below for the volume beneath it.
- **forget allocates nothing**: it takes each of the volume's dirty nodes out of the map where it is, looking at the
  slot again as `map_remove` moves a later key back, so going back for want of memory drops every node whose block the
  container gave back. The hosted index test forgets with every allocation failing and finds no dirty node left.
- **A live query waiting is answered** when the live queries begin again after a going back (`restart_lives`), with
  Resync, as `indexes_changed` does.
- **The shell's query**: a text, quoted or a name's, is read for a predicate's words only when it's the type's one
  argument; among several it's one value, however it's spaced or whatever it says (`title == "to do"`, `directories ==
  "and"`). Nots and parentheses nested past `MAX_TERMS` are refused before the shell's stack runs out. The search
  test adds both.
- **Bare words**: one argument alone for a list of text is the list itself only when its value is a list (a `[list]`,
  or a `$name` holding one), decided once it's evaluated (`unwrapped`); a text alone is the list's one item, so `wc
  "my file.txt"` works. The C-from-the-shell test runs `wc "libc_words.txt"`.
- **Log sources of programs a shell runs** are named `s<session>_<program>` (`events_for`), so a shell can't write as,
  or set the budget of, a system's source such as `clock`, nor another session's; a name too long with its prefix
  (past the events service's 32 bytes) gets no ring. The C-from-the-shell test expects `[user]
  s0_test_libc_files: ...` and refuses the bare name.
- **A program's memory is a share**: no fixed cap (`MAX_PROGRAM_BUDGET` is gone); the shell gives what a bundle asks
  for when its budget has that much uncharged beyond `SHELL_RESERVE` (8 MiB, `program_room`), and refuses with what it
  has to give otherwise. Its budget growing from the session's isn't built: a launch's budget is split off the
  launcher's own (std's `launch_named`), and a budget's limit can't grow, so it needs either a launch option naming the
  budget to split from, in Hemera's std, or a call to grow a budget; the shell's stays 40 MiB, so a program gets at
  most about 30 MiB now. Not tested past Lua's 16 MiB: no program asks for more than the shell has.
- **Judged not real, or left**: none of part A's findings were judged not real.

## As Built: 21i, the review, part B (2026-11-27)
A read-only review of 21a to 21h, each finding checked against the code before it was fixed; this part takes the
kernel's, the USB hot-plug's, the sockets' and the docs', and the owner's loopback, LLVM and connector decisions.
- **cpu_budget_cpus bounded**: it wrote a word at a time for as many words as the caller's buffer had, so a 1 GiB
  buffer held a CPU for seconds; it writes at most `CPU_SET_WORDS` (64, a set of 4096 CPUs) in one copy now, the words
  past those left as they were. test_affinity gives it 100 words and sees 64 written, the rest untouched. The
  package's doc of `cpu_budget_cpus` ("zeros in any past them") wants "up to 64 words" — a Hemera doc line, left for
  the merge, as this part changes no Hemera.
- **USB hot-plug**: a host controller's driver that ends for good (ended too often, not restarted, or not started
  again) lets go of what it had found (`forget_usb_controller`), so its class drivers don't run on for dead
  interfaces; a disk plugged in after the storage manager ended for good starts it again, its restarts counted afresh,
  given every disk there is, as a new disk is cause to try once more. The supervisor's connectors are reused once an
  unplug frees them (`freed`, set by `detach_usb`); others aren't, as `dials_of` counts their dials. A test-only
  `test_connector_room=N` limits the places to those in use once start-up's are started plus N: the keyboard test,
  with room for 1, sees its second plugging in take the place the first freed (`supervisor: connector % reused`) and
  never `no room for another connector`.
- **The USB stick's replug checked**: the storage manager says `a disk was plugged in and held, N plugged in so far`
  once `add_disk` has held it and listed its partitions, or that it isn't held; the stick test waits for the replug's
  own line and refuses the other. The first stick, which starts the storage manager, comes with its start, not on the
  devices channel, so the replug is the first counted.
- **Sockets**: `accept` takes its port before it makes the descriptor, and a connection it can't serve is closed at
  once and its descriptor freed, rather than through `close_socket`'s wait of up to 5 s for bytes never written;
  `select` leaves out a descriptor poll woke for that has no bit to set (one only in `errors` that hung up), polling
  the rest again for what's left of the timeout, so it never answers 0 early, and counts a hung-up descriptor as
  writable. `listen` asks for its first connection at once, and `accept` the next, a backlog of one, so a client's
  handshake finishes before accept is called.
- **The loopback interface** (the owner's): net_stack keeps what it sends to 127.0.0.0/8, ::1 or its own addresses
  (`loop_back`, `LOOPED` 32 packets) and takes it back as though it had arrived (`deliver_looped`), TCP, UDP and an
  IPv4 echo, with no device; a loopback destination's source is the destination itself (`source_v4_for`, and
  `source_for` for ::1), so answers come back to it; a loopback source or destination from the link is dropped. TCP
  holds back while the looped are nearly full (`outbox_full`), and the network service takes them back on each pump,
  a few rounds at a time, its timer set at once for what's left. Only with a NIC: without one there's no stack.
  Tested hosted (`loops_datagrams_back`: 127.0.0.1, the stack's own address and ::1, nothing on the link) and from C,
  c/sockets.c's client and server of its own over 127.0.0.1 and ::1, 64 KiB echoed and a datagram there and back.
- **C's compiler found without a machine's path**: `tools/c_libraries.py`'s `LLVM_RELEASES` are an installer's
  (`C:/Program Files/LLVM`) and Linux's `/usr/lib/llvm-*`; a release unpacked elsewhere is named by `LLVM` or `CLANG`
  (docs/guides/building.md's table). Without one with RISC-V, RISC-V's C goes through Hemera's `llc` again, as before
  21g. On the development machine the boot and unit tests are run with `LLVM` set to the 23.1.5 release unpacked under
  `D:/Programs/System Tools`.
- **The coverage fuzz test checks its guidance**: on a kernel with counters the fuzzer expects some reached and says
  `guided by the kernel's coverage, N of its M counters reached`, which the test expects, refusing the line it says
  when it found none.
- **Docs**: the platform calls' `@error` lists name `MissingRight` for `RIGHT_PLATFORM_DEVICES` (or `_POWER`);
  `debug attach` pages through `process_threads`, so a thread past the first 64 is found, and every thread is
  suspended and resumed.
- **Tests**: test_affinity, the debugger's attach, both hot-plug tests, the sockets from C (the loopback's lines
  among them), the coverage fuzz test and the libc's, on all three (23 of 23; the coverage test on x86-64 and AArch64,
